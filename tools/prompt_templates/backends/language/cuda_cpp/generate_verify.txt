@@ checklist_g5
G5 — io_contract consistency: no constant/fixed-JSON/analytic-expression output unrelated to the model computation; each output parameter's (and returned value's) final expression tree reaches the `io_contract.semantic_dependency.required_sources` and `io_contract.outputs` variables. The host-rendered driver captures exactly what a published operation leaves in the host arrays `drive` binds, so what the operation returns in them is the raw evidence: a state kept in a private copy, or left only in device memory, while the argument holds a placeholder, an `out` array with a cell left unassigned on a true result, an input-updated array left unadvanced on a true result, or a result logical that does not state what the IR defines it to state (true for a step the operation did not complete, or set from a constant rather than from the guard the IR names) is a fail. Private namespace-scope state between the initialization operation and the step operation is admitted and is captured in no file; `init` must establish every private field a later call reads, because the driver does not reset it between cases. **The host's predicates over the captures decide each test, and the model judges nothing.**
@@ checklist_g6_floor_scope
A pointwise operation — a `component` operation every argument of which is a scalar or a fixed-extent view, which the host-rendered header declares, and the source defines, `__host__ __device__` — launches nothing, and its plan declares `"model": "none"` because its consumers' kernels call it once per element: that is the binding, not a finding, and no residency round trip arises for it; hold its body to device-legal code (no standard-library container or string, no allocation, no exception, no I/O) and to the IR's algorithm. Scope your judgment: on a `component`/`problem` node whose target is gpu+cuda+cuda_cpp, whose plan does not explicitly decline CUDA and whose model source has counted `for` loops, the "not one kernel anywhere" case is already settled deterministically by the `Generate.gate` static check before you see the source, so judge whether the kernels present COVER the loops the plan names, with the launch shape it states, and whether the operation's allocation, transfer and launch shape is the one its plan states — or, where the plan says nothing about it, the producer's default: a device buffer allocated once at namespace scope and reused, each input copied in once and each output copied out once per call with intermediates kept on the device — save where a host function's arguments need them in host memory (a dependency whose operation is not `__host__ __device__` takes host views, so the state crosses the bus around each call of it, and that copy is part of the default) — element-wise device work launched once over the whole range rather than once per element from a host loop, and a `__host__ __device__` dependency called from inside that kernel — not whether any kernel exists. That default is a recommendation, not a rule: a plan that states another shape with a reason about the operation (a buffer sized per call because the extents vary) is the producer's own claim, and you hold the source to it. A `__host__ __device__` dependency called from a host loop rather than inside a kernel keeps that loop on the host, which is held as a loop the plan keeps on the host (below). The finding is a source that departs from the stated shape, or from the default while the plan is silent — not the choice itself. That floor does not run on any other node kind, on a model source with no counted `for` loop, or when the plan's parallelization explicitly names `none` or some other model, so in those cases existence is still yours to judge. A declared `none` is the producer's own claim, and the deterministic floor trusts it: hold it to the loops, and a plan that says `none` over loops that are plainly parallelizable on the device is itself the finding. Whatever the plan, a HOST FALLBACK is a fail: a path that, when a CUDA call fails (an allocation, a copy, a launch, a synchronize), computes the kernel's result on the host instead of stopping — it lets a run whose kernels never executed produce correct-looking state. Checking a CUDA call's return and, on a failure, returning without the result — a persistent buffer stays allocated — is the device plumbing that rule requires, not a branch the IR omits (G4); so is the default's capacity branch over a kept buffer (allocate it on the first call that needs it, replace it with a larger one when a later call needs more), which the producer is told to write. The deterministic floor only asks that a kernel EXIST — a `__global__` definition or a `<<<` anywhere satisfies it — so it does not tell you the loops run on the device: a loop the plan's parallelization puts on the device that the source computes on the host is a fail, whether beside a kernel that does not do that loop's work (a stub launched to satisfy the floor) or behind a branch that sends the cases the run covers to the host (a size threshold above every case). A loop of the model source the plan keeps on the host is the plan's own claim, held like a declared `none`: its stated reason must be about the loop itself (a carried dependence, a reduction you cannot express correctly, a copy that only reshapes host state) — a reason about a gate, or about a run in which a kernel did not execute, is not one — and a plainly parallelizable loop of the model source kept on the host without such a reason, or left out of the plan altogether, is the finding. The launch configuration is the host's, whatever the plan: the run's threads per block is `spec2science::launch_block_size` (the host-rendered header declares it and the host-rendered runner sets it, before the first case, to the block size the host imposed on the run), and the host runs the binary once more per block size of the target's execution-shape sweep and compares each run's state with the reference. Every kernel launch takes `spec2science::launch_block_size` threads per block — read when the operation runs, never copied into a namespace-scope variable initialized before `main` — with a grid computed from it to cover the range (a multi-dimensional block is a product equal to it), shared memory and block-level reductions sized from it at run time, and a grid-stride loop striding by `gridDim.x * blockDim.x`; a launch with a literal block size, one chosen from the device's properties or an occupancy query, or a block size that differs between launches is a fail (the `Generate.gate` static check has already refused a source that launches and never names `spec2science::launch_block_size`, or that writes it, so a source you see names it — judge each launch, not the name's presence): it makes the comparison across block sizes compare runs of one configuration. A tile, a shared-memory array or a reduction tree whose correctness needs one particular block size is a fail too, even when the block size the certifying run uses gives the right state.
