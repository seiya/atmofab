@@ checklist_g6_floor_scope
Scope your judgment: on a `component`/`problem` node whose target is cpu+mpi+fortran and whose plan does not explicitly decline MPI, a direct use of the message-passing library, a residency other than `distributed`, the absence of any partition or halo-exchange call, a checks module that sets no partition axis, and a component model source that names any harness operation are already settled deterministically by the `Generate.gate` static check before you see the source; judge what that floor cannot see. A component's published operations are called by consumers on their own rank's block, so they must compute exactly what the spec says over the arrays they are handed, the distribution living in the component's checks module; a problem calls its components on its own block with the halo filled between calls — a problem that hands a component the global array or a component operation that assumes it is handed the global array is the finding. The ranks form a process grid the HOST chooses (`p1 × p2`, from `(ranks, 1)` to `(1, ranks)`), reported by the harness's `__grid_dims` / `__grid_coord`; the producer is told to partition the first spatial axis of the state along grid dimension 1 and the second along grid dimension 2. Whether the decomposition is right for every case the tests run and on every grid — the owned ranges along each dimension, a ghost width at least the stencil's reach, a halo exchange along every partitioned axis before every stencil read that crosses it, with the spec's periodicity for that axis, and along dimension 1 then dimension 2 when the stencil reads a corner; whether each rank computes only the cells it owns (a kernel that computes the whole range on every rank and reports a partition passes every deterministic check, and is the finding); whether the kernel ever chooses, computes or assumes a grid of its own, or partitions a two-dimensional state along one grid dimension only (on a grid with `p2 > 1` the ranks of a line then compute the same copy, the state still agrees, and it is the finding); whether the `sb_<var>_axis<d>` / `_lo<d>` / `_hi<d>` / `_glo<d>` values describe the cells the rank actually contributes along each grid dimension to the global array as the IR declares it (the first and last ranks along a dimension also contribute the domain's boundary ghost cells when the declared shape includes them); and whether every global quantity a check or a metric reads goes through a harness reduction — a check computed over rank 0's own cells alone passes on one process and is wrong on several, and a sum over a copy every rank of a line holds counts it once per rank unless only the coordinate 0 adds it. The producer is told one exception to distributing: a case whose grid cannot give every rank `m_d` cells along every partitioned axis — `m_d` the larger of the `ng` cells the halo exchange requires and the smallest block extent the operations the case calls on a block accept (fewer than `p_d * m_d` cells along the axis partitioned along grid dimension `d`) — is computed replicated, both `sb_<var>_axis<d> = 0`, decided identically on every rank. Hold the kernel to exactly that threshold: a replicated branch taken by a case that could be distributed, or a partition that exists only in a branch no case the tests run reaches, is the finding. A plan that declines MPI is the producer's own claim: hold it to the kernel.
