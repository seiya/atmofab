@@ target_lowering_floor
For a `cpu` target whose `parallel.backend` is `mpi` and whose language is `fortran`, the program runs as `execution.ranks` processes started by the target's launcher, and the host re-runs it as ONE process for its quality check — the two runs must report the same checks and verdict, so every value a check or a metric reads must be the global one, whatever the number of processes. The default lowering is a block decomposition of the state along one axis, declared as `"parallelization": {"model": "mpi", ...}` and `"decomposition": {"axis": <k>, "model": "block_1d"}`, with `"state_residency": "distributed"` and `distributed_state@1` added to `capability_requirements`. The message-passing runtime is reached ONLY through the target's harness: a `use <harness>_model, only: <names>` naming only the distributed-state operations the host-rendered runner's comment lists (the partition, the halo exchange, the rank queries, the reductions) — `use mpi`, `use mpi_f08`, `include 'mpif.h'` and a call of or reference to any procedure whose name starts with `mpi_` are refused deterministically, and so is a harness `use` with no `only:` list or naming anything else (the writers, the emitters, the gathers and the start and end of the runtime are the runner's). In `case_setup` get this rank's owned global range with `call <harness>__partition(n_global, glo, ghi)` (a rank may own nothing: `ghi < glo`), allocate the local arrays over the owned cells plus the ghost width the stencil reaches (allocate them even when the rank owns nothing), and set, for EVERY bound array, the four partition variables the runner imports: `sb_<var>_axis` (the axis it is split along; 0 when it is replicated, i.e. every rank holds the whole array), `sb_<var>_lo` / `sb_<var>_hi` (the indices, in the array's own declared bounds, of the owned cells along that axis, ghost cells excluded) and `sb_<var>_glo` (the global index, from 1, of the cell at `lo`); only the partitioned axis may carry ghost cells, every other axis holds exactly its global extent, and the halo exchange takes an array whose partitioned axis holds `ng` ghost cells, the owned cells, then `ng` ghost cells. Before a stencil reads a neighbour's cell, fill the ghosts with `call <harness>__exchange_halo_r<k>(...)`, with `periodic` from the spec's boundary rule — the exchange is what a periodic copy of the edges becomes — and let each rank compute only the cells it owns. The halo exchange requires EVERY rank to own at least `ng` cells (the harness stops the run otherwise), and the run has `execution.ranks` processes while the quality check has one: a case whose grid is too small to give every rank `ng` cells is computed replicated instead (every rank holds the whole array, `sb_<var>_axis = 0`, no exchange), decided from the case's grid and `<harness>__comm_size()` — the same decision on every rank. `case_run` reports the cells THIS rank updated (the runner sums them). A check or a metric over the whole field goes through `<harness>__reduce_sum` / `__reduce_max` / `__reduce_min` / `__reduce_sum_int`, which every rank calls in the same order: they are collective, and so are the halo exchange and the runner's gathers. The floor here is deterministic: on a `component` or `problem` node the `Generate.gate` static check FAILS a source that reaches the runtime directly, and — unless your plan's parallelization `model` explicitly names `none` (or another model) — a plan whose `state_residency` is not `distributed`, sources with no statement calling `<harness>__partition` or `<harness>__exchange_halo_r<k>` by that name (a renamed alias is not recognized), and a checks module that never sets a bound array's `sb_<var>_axis` to anything but 0. When the computation genuinely cannot be distributed, declare `"model": "none"` and say why in the plan for the reviewer, who holds that declaration to the kernel; the reviewer also checks that each rank computes only what it owns and that the partition variables describe what it owns, so satisfying the floor alone is not the bar.
