@@ target_lowering_floor
For a `cpu` target whose `parallel.backend` is `mpi` and whose language is `fortran`, the program runs as `execution.ranks` processes started by the target's launcher, arranged in a two-dimensional process grid of `p1 × p2` ranks that the HOST chooses — the run may be `(ranks, 1)`, `(1, ranks)` or any grid between, and the host re-runs the program as ONE process for its quality check — and every run must report the same checks and verdict, so every value a check or a metric reads must be the global one, whatever the number of processes and whatever the grid. Ask the grid with `call <harness>__grid_dims(p1, p2)` and this rank's coordinates with `call <harness>__grid_coord(c1, c2)`; never choose, compute or assume a grid. The default lowering is a block decomposition over that grid: the first spatial axis of the state partitioned along grid dimension 1 and the second spatial axis along grid dimension 2 (a one-dimensional state along dimension 1 only, every rank of a line along dimension 2 then holding the same copy), declared as `"parallelization": {"model": "mpi", ...}` and `"decomposition": {"model": "block_grid", "grid": "harness", "dim1_axis": <k>, "dim2_axis": <k or 0>}`, with `"state_residency": "distributed"` and `distributed_state@2` added to `capability_requirements`. The message-passing runtime is reached ONLY through the target's harness: a `use <harness>_model, only: <names>` naming only the distributed-state operations the host-rendered runner's comment lists (the grid queries, the partition, the halo exchange, the rank queries, the reductions) — `use mpi`, `use mpi_f08`, `include 'mpif.h'` and a call of or reference to any procedure whose name starts with `mpi_` are refused deterministically, and so is a harness `use` with no `only:` list or naming anything else (the writers, the emitters, the gathers and the start and end of the runtime are the runner's). In `case_setup` get this rank's owned global range along each partitioned axis with `call <harness>__partition(n_global, d, glo, ghi)`, `d` the grid dimension that axis is partitioned along (a rank may own nothing along it: `ghi < glo`), allocate the local arrays over the owned cells plus the ghost width the stencil reaches on each partitioned axis (allocate them even when the rank owns nothing), and set, for EVERY bound array, the eight partition variables the runner imports, one group per grid dimension `d` = 1, 2: `sb_<var>_axis<d>` (the array axis partitioned along grid dimension `d`; 0 when the array is not partitioned along `d`; 0 in both groups when it is replicated, i.e. every rank holds the whole array), `sb_<var>_lo<d>` / `sb_<var>_hi<d>` (the indices, in the array's own declared bounds, of the cells this rank contributes along that axis to the GLOBAL array — the array as the IR's `shape_expr` declares it) and `sb_<var>_glo<d>` (the global index, from 1 in that shape, of the cell at `lo<d>`). A halo cell — a copy of a neighbour's cell — is never contributed; when the declared shape includes the domain's boundary ghost cells, the first rank along `d` contributes the leading ones and the last the trailing ones, so the gathered array has exactly the declared shape; every axis not partitioned holds exactly its declared extent, and along a dimension the array is not partitioned along only the coordinate 0 of that dimension contributes its copy (the gather reads it there). The halo exchange along grid dimension `d` takes an array whose partitioned axis holds `ng` halo cells, the owned cells, then `ng` halo cells, and fills them at every position of the array's other axis, its halo cells included. Before a stencil reads a neighbour's cell, fill the ghosts with `call <harness>__exchange_halo_r<k>(...)` along every partitioned axis the stencil reaches across, with `periodic` from the spec's boundary rule for that axis — the exchange is what a periodic copy of the edges becomes — and when a stencil reads a diagonal neighbour (a corner halo cell), exchange along dimension 1 first and then along dimension 2: the second exchange carries the halo cells the first one filled. A stacked state (a component axis beside the spatial ones) is exchanged one component slice at a time. Let each rank compute only the cells it owns. On a `component` node the distribution lives in the checks module alone: every consumer calls the component's published operations on its OWN rank's block, so each operation keeps computing exactly what the spec says over the arrays it is handed — `case_setup` partitions and allocates this rank's block, `case_run` fills its halo with the exchange and then calls the unmodified operation on the block — and a component's model source names no harness operation at all (an operation that partitions, exchanges, asks the grid or reduces inside itself distributes an already distributed block a second time, and the `Generate.gate` static check refuses it). A `problem` node drives its components the same way: it calls them on its own block, with the halo filled between the calls. The halo exchange requires EVERY rank to own at least `ng` cells along the dimension it exchanges along (the harness stops the run otherwise), and the grid varies from run to run while the quality check has one process: a case whose grid cannot give every rank `ng` cells along every partitioned axis (fewer than `p_d * ng` cells along the axis partitioned along grid dimension `d`) — and only such a case — is computed replicated instead (every rank holds the whole array, both `sb_<var>_axis<d> = 0`, no exchange), decided from the case's grid and `<harness>__grid_dims` — the same decision on every rank. `case_run` reports the cells THIS rank updated (the runner sums them; a copy held by every rank of a line is counted on the coordinate 0 of that line only). A check or a metric over the whole field goes through `<harness>__reduce_sum` / `__reduce_max` / `__reduce_min` / `__reduce_sum_int`, which every rank calls in the same order: they are collective, and so are the halo exchange and the runner's gathers; a sum over an array held whole along a grid dimension adds each copy once per rank of that line, so such a sum takes its terms on the coordinate 0 of that dimension alone. The floor here is deterministic: on a `component` or `problem` node the `Generate.gate` static check FAILS a source that reaches the runtime directly, and — unless your plan's parallelization `model` explicitly names `none` (or another model) — a plan whose `state_residency` is not `distributed`, sources with no statement calling `<harness>__partition` or `<harness>__exchange_halo_r<k>` by that name (a renamed alias is not recognized), and a checks module that never sets a bound array's `sb_<var>_axis1` or `sb_<var>_axis2` to anything but 0. When the computation genuinely cannot be distributed, declare `"model": "none"` and say why in the plan for the reviewer, who holds that declaration to the kernel; the reviewer also checks that each rank computes only what it owns, that each spatial axis is partitioned along the grid dimension stated above, and that the partition variables describe what it owns, so satisfying the floor alone is not the bar.
