## 1. Test purpose
This suite verifies the published `operation` `dynamics_shallow_water_reconstruction_2d_muscl_mc__reconstruct` at `L0`: the exact reconstruction of a bilinear field (linear along each index, with a slope that depends on the other index), the invariance of a constant field, the zero slope at a local extremum and beside a step, the value of the `MC` slope on a field where each of the three arguments of the minimum is the smallest in some cell, the three symmetry pairs the reconstruction admits, and the input guard for each clause of the Controlled Spec §4 that a captured state can observe: a ghost width below two (`ng<2`) and a padded extent that disagrees with `nx`, `ny`, `ng` (`nx_total/=nx+2*ng`, `ny_total/=ny+2*ng`), each of the two padded extents both too large and too small, together with the zero-filled interface arrays §4 requires on a rejected input. The extent clauses `nx<1` / `ny<1` have no case: a state of zero extent has no snapshot the judgment could read, so those two clauses are stated by the Controlled Spec and not observed by this suite. The clause that no element of `U_in` is read on a rejected input is likewise stated by the Controlled Spec alone: a read leaves no trace in the captured state. So is the call itself, because every judged state variable is written by the checks module, so a checks module that fabricates the interface arrays instead of calling the `operation` is not excluded here.

The symmetry pairs (`docs/TESTS.md` §Symmetry pairs) are carried on the cubic case. The **axis exchange** transposes the padded field and exchanges `nx` with `ny` and `nx_total` with `ny_total`; the `x`-interface states of the transposed field are the base's `y`-interface states transposed, and the reverse: `U_L' = U_B^T`, `U_R' = U_T^T`, `U_B' = U_L^T`, `U_T' = U_R^T`. The **`x` mirror** reverses the padded field along the first axis: the two sides of an `x` interface exchange roles and the interface numbering reverses, `U_L'(m,j) = U_R(nx+2-m, j)` and `U_R'(m,j) = U_L(nx+2-m, j)`, and the `y`-interface states are reversed along the first axis, `U_B'(i,n) = U_B(nx+1-i, n)` and `U_T'(i,n) = U_T(nx+1-i, n)`. The **`y` mirror** is the same with the roles of the two axes exchanged: `U_B'(i,n) = U_T(i, ny+2-n)`, `U_T'(i,n) = U_B(i, ny+2-n)`, `U_L'(m,j) = U_L(m, ny+1-j)`, `U_R'(m,j) = U_R(m, ny+1-j)`. The operation reconstructs one scalar field, and the limited slope is odd in the field (`sigma(-a,-b) = -sigma(a,b)`, Controlled Spec §3), so the sign reversal a mirror carries on the mirrored momentum component commutes with the reconstruction; the mirror pairs reverse the field without negating it, as the mirror maps `h`. The cubic case is the base because its one-sided differences are positive along both axes at every cell and each argument of the `MC` minimum is the smallest in some cell: the axis exchange runs its `x` data through the `y` path and its `y` data through the `x` path, and each mirror makes every difference along the mirrored axis negative, which no other case of this suite has (the bilinear field's differences are positive, and the constant, extremum and step fields have a zero slope at every cell). The transformed cases are judged against the base by the pair, not by tables of their own: the base is pinned element by element by `l0_mc_slope_value_pass`, and the pair pins each transformed case to the base. A pair establishes the transformed reconstruction only as the checks module captures it: a checks module that writes the transformed base arrays instead of calling the `operation` at the transformed case's arguments captures the same arrays, and the call is the `Generate` reviewer's to hold (`docs/workflow/CHECKS_MODULE_CONTRACT.md` §1). The translation is not a pair: the reconstruction is a stencil of fixed width that does not depend on the position of a cell, so a translated field gives the translated interface states trivially, and the cases' fields are not periodic.

## 2. Input-defaulting rules
- Every normal case uses `nx=6`, `ny=4`, `ng=2`, `nx_total=10`, `ny_total=8`. The field `U_in` is given on the whole padded array, ghost cells included, by a formula of the padded indices `i=1..10`, `j=1..8`; the ghost cells hold the same formula as the interior, because the operation reads them (Controlled Spec §2) and no boundary `component` runs in this suite. The `x` interfaces are `m=1..7` (`nx+1` values) and the `y` interfaces `n=1..5` (`ny+1` values), numbered as in the Controlled Spec §2: `x` interface `m` lies between the padded columns `m+1` and `m+2`, `y` interface `n` between the padded rows `n+1` and `n+2`; the interior row `j=1..4` is the padded row `j+2` and the interior column `i=1..6` the padded column `i+2`.
- The bilinear case uses the field `U_in(i,j) = 1 + 0.3*i + 0.2*j + 0.1*i*j`. Along every padded row `j` the field is linear in `i` with the slope `0.3 + 0.1*j`, and along every padded column `i` it is linear in `j` with the slope `0.2 + 0.1*i`, so the `x` slope of a cell differs from row to row and the `y` slope from column to column; a slope evaluated on a row or column other than the cell's own is visible.
- The constant case uses `U_in(i,j) = 2.5`.
- The extremum case uses `U_in(i,j) = 1` at every cell except `U_in(5,4) = 3` (the interior cell `i=3`, `j=2`).
- The step case uses `U_in(i,j) = 0` for `i<=5` and `U_in(i,j) = 1` for `i>=6`, at every `j` (a step between the interior columns `3` and `4`).
- The cubic case `l0_cubic` uses `U_in(i,j) = (i-5)^3 + (j-4)^3`. Its one-sided differences in `x` are `a = 3c^2 - 3c + 1` and `b = 3c^2 + 3c + 1` with `c = i-5`, both positive at every cell, and the three arguments of the `MC` minimum are `2a`, `2b` and the central difference `3c^2 + 1`; the `x` slope at the padded columns `2..9` is `28, 13, 2, 1, 2, 13, 28, 49`, the smallest argument being `2b` at column `4`, the central difference at columns `2, 3, 5, 7, 8, 9`, and `2a` at column `6`. The `y` slope at the padded rows `2..7` is, by the same formula in `c = j-4`, `13, 2, 1, 2, 13, 28` (`2b` at row `3`, `2a` at row `5`, the central difference elsewhere). At column `5` and at row `4` the three arguments are `2, 2, 1`, so the central difference is the strict minimum there too.
- Three transformed copies of `l0_cubic`, each sorting after it, are the symmetry-pair cases of §1, each with `ng=2` and its field given on the whole padded array, ghost cells included:
  - `l0_cubic_axis`: `nx=4`, `ny=6`, `nx_total=8`, `ny_total=10`, `U_in'(i,j) = U_in(j,i) = (j-5)^3 + (i-4)^3` for `i=1..8`, `j=1..10`. Its one-sided differences are positive along both axes.
  - `l0_cubic_xmir`: `nx=6`, `ny=4`, `nx_total=10`, `ny_total=8`, `U_in'(i,j) = U_in(11-i,j) = (6-i)^3 + (j-4)^3`. Every one-sided difference along the first axis is negative.
  - `l0_cubic_ymir`: `nx=6`, `ny=4`, `nx_total=10`, `ny_total=8`, `U_in'(i,j) = U_in(i,9-j) = (i-5)^3 + (5-j)^3`. Every one-sided difference along the second axis is negative.
- The abnormal cases each violate exactly one clause of the Controlled Spec §4, with the bilinear field on the padded array their extents define. The invalid-`ng` case uses `ng=1` with `nx=6`, `ny=4`, `nx_total=8`, `ny_total=6`. The two invalid-`nx_total` cases use `nx=6`, `ny=4`, `ng=2`, `ny_total=8` with `nx_total=11` (`U_in` allocated `11` × `8`, one column too many) and with `nx_total=9` (`9` × `8`, one column too few). The two invalid-`ny_total` cases use `nx=6`, `ny=4`, `ng=2`, `nx_total=10` with `ny_total=9` (`10` × `9`) and with `ny_total=7` (`10` × `7`). Each padded extent is violated on both sides so that a guard written as an inequality (`nx_total<=nx+2*ng`) accepts the too-small case, and one written as an equality against the wrong sum accepts neither.

## 5. Diagnostics contract
- Require outputting `checks.bilinear_exact`, `checks.constant`, `checks.extremum`, `checks.step_bounded`, `checks.slope_value`, `checks.symmetry_pair`, `checks.rejected_outputs_zero`, and `checks.input_guard` in `diagnostics.json`. `checks.symmetry_pair` reads the interface arrays of `l0_cubic`, which the checks module keeps from that case's run (`docs/workflow/CHECKS_MODULE_CONTRACT.md` §2, the accumulator ordering rule: each transformed case sorts after its base).
- `pair_residual` of a transformed case and one interface array `q` (`U_L`, `U_R`, `U_B` or `U_T`) is `norm2(q - T_q(base)) / norm2(T_q(base))` over every element, where `T_q(base)` is the array of `l0_cubic`, captured after its run, that §1 maps to `q`, transposed (`_axis`) or reversed along the mirrored axis (`_xmir`, `_ymir`). The host evaluates it from the captured states (`at('l0_cubic')` with `transpose` and `flip`, `docs/workflow/phases/phase_01_compile.md`); the transformation preserves the `l2` norm, so the normaliser is the `l2` norm of the base array it reads.
- The state of a case, captured after setup and after the run, consists of `U_in` (`nx_total` × `ny_total`, the input field, ghost cells included), `U_L` and `U_R` (`nx+1` × `ny` each), `U_B` and `U_T` (`nx` × `ny+1` each), and `grid_valid` (scalar: `-1` at setup, before the `operation` is called; `1` when the `operation` returned true; `0` when it returned false). `U_in` is set at setup; every element of the four interface arrays is set to the sentinel value `-999` at setup, before the `operation` is called, and they are the arrays the `operation` wrote at the capture after the run — the sentinel is not a value the `operation` produces on any case of this suite, so a captured `0` in an interface array is a zero the `operation` wrote, which is what the abnormal cases judge, and an array the `operation` left untouched captures `-999` and fails; `grid_valid` is set to `-1` at setup and to the value the `operation` returned at the call, recorded as `1` / `0` because a state variable is real-valued. The setup value `-1` is distinct from both values the `operation` can return, so a case whose `operation` was not called, and whose flag was therefore not written after setup, captures `-1`, which no judgment of §6 accepts. This does not establish that the `operation` was called: the flag is a state variable the checks module owns, so a checks module that writes `0` into it without calling the `operation` captures the same value as a rejected input. What the setup value excludes is the omission of the call, not the fabrication of its result; the fabrication of the whole judged state is outside what this suite can observe and is stated in §1. No state variable is derived by the checks module after the run: a deviation, a maximum or a bound over these variables is a `checks.<id>` status, never a state variable. Every judgment of §6 is a statement about these variables and the §2 inputs. The expected interface arrays of every normal case other than the three transformed cases, which are judged against `l0_cubic` through `pair_residual` — the closed forms and tables of §6, evaluated on the case's own grid — are declared inputs of the case, stated in full as arrays, so that a host-evaluated judgment compares each captured interface array to its expected array element by element rather than through a sum, a minimum or a maximum, which a permutation of the elements would satisfy.
- Each check is computed on the case named here and is `na` on every other case: `checks.bilinear_exact` on the bilinear case; `checks.constant` on the constant case; `checks.extremum` on the extremum case; `checks.step_bounded` on the step case; `checks.slope_value` on the cubic case; `checks.symmetry_pair` on the three transformed cases; `checks.rejected_outputs_zero` on every abnormal case; `checks.input_guard` on every case (`pass` when `grid_valid = 1`, `fail` when `grid_valid = 0` and when `grid_valid = -1`).
- `cross_target_state_agreement` compares this target's run with every other target's certified variant of this node, case by case (`docs/TESTS.md` §Cross-target judgment): for one output `q` captured after the run and the same output `q_ref` of the same case in the other variant, it is `max|q - q_ref| / max(max|q|, max|q_ref|, 1)` over every element. The host evaluates it from the captured state, against each other variant separately; it is not a `diagnostics.json` field, and on a target with no other certified variant it holds vacuously.
