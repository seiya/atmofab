# Runtime dependencies of the HOST that runs the conductor. Authority for what belongs here is
# the package table in `docs/RUNBOOK.md` §0-1 ("Refused at startup —
# missing_required_python_modules"); `tools/tests/test_dependency_declaration.py` checks this
# file against it in both directions. No leaf needs any of these.
#
# Versions: a pin is a value MEASURED on the development host and recorded here, so a second
# machine installing from this file becomes the machine the measurements were taken on. A floor
# is used only where a pin is not installable; the comment then says why the floor is enough.
#
# Supported Python: 3.10. That is the interpreter every measurement in this repository was
# taken on, and the one CI installs (`.github/workflows/tests.yml`). It is recorded here
# rather than as `python_requires` metadata because this repository is not a distributed
# artifact (`AGENTS.md` §Development premises), so there is no package to carry the field;
# what enforces it is CI running on that version, not a declaration.

# FLOOR. The development host carries 5.4.1 from apt, and pip cannot reproduce it on Python 3.10
# (the 5.4.1 sdist builds against Cython 3 and fails), so the measured value is not a pinnable
# one. The floor is enough because the only compatibility break in the 5.x -> 6.x line is
# `yaml.load` without a `Loader=`, and this tree has zero of those: every one of its YAML reads
# is `yaml.safe_load` (measured at 738fca4: 20 call sites, 0 bare `yaml.load`).
PyYAML>=5.4

# PIN, measured on the development host. `tools/backends/language/fortran/structure.py` uses the
# `Language(tree_sitter_fortran.language())` / `Parser(language)` spelling, which is the one this
# API has changed across py-tree-sitter releases, so an unbounded declaration would let a machine
# install a version the gate cannot drive.
tree-sitter==0.26.0

# PIN, measured on the development host, and the version `docs/RUNBOOK.md` §0-1 records the
# Fortran structure front end as "written against".
tree-sitter-fortran==0.6.0
