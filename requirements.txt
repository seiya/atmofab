# 5.4.1 from apt and pip does not reproduce it on Python 3.10 (the 5.4.1 sdist builds against

# installed into a scratch `--target` and put ahead on `PYTHONPATH` — 5793 passed, 3039 subtests,
# 0 skipped, 0 failed. So the floor's range is covered end to end by a run rather than by a
# survey of release notes. The cap is `<7`, because 7 does not exist and therefore has not been
# measured, and this file's rule is that installing from it reproduces a measured machine.
#
# One correction to the reason an earlier version of this comment gave. It said "every one of its
# YAML reads is `yaml.safe_load` (20 call sites, 0 bare `yaml.load`)". Re-measured at 738fca4 by
# walking every `*.py` with `os.walk`: 19 `yaml.safe_load`, 0 bare `yaml.load`, and one further
# read that is neither — `tools/llm_config.py:788`, `yaml.load(text, Loader=_NoDuplicateKeyLoader)`
# over a `yaml.SafeLoader` subclass that installs its own mapping constructor. That reader depends
# on PyYAML's EXTENSION surface (`SafeLoader` subclassing, `construct_mapping`,
# `resolver.BaseResolver.DEFAULT_MAPPING_TAG`), which a `yaml.load`-spelling survey does not cover
# at all — which is why the justification is now the suite run above and not the survey.
