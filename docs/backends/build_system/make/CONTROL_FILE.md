## 1. Authorship and the object rules

The file names, module artifacts and compiler flags in the rules below (`<dep>_model.f90`, `.mod`, `gfortran -J`) are the `fortran` binding's, the one language that declares `control_file` today; a language's own `control_file` rules supply its values (`tools/backends/language/<language>/control_file.py`).

- **`src/Makefile` authorship:** for any node whose target's language also declares `control_file` (today `fortran`) — **leaf or with dependencies** — the conductor authors `src/Makefile` host-side (runtime-owned, like `lineage.json`; not in the generate leaf's `allowed_output_paths`). For a dependency node it adds the closure object rules (Model B), each `<dep>_model.f90` staged into `$(OBJDIR)` at Build. The Makefile rules below document what that authored Makefile satisfies and what a leaf-authored one, for a language that declares no `control_file`, would have to produce.
- The generated `src/Makefile` makes explicit the object dependencies corresponding to the `use` dependencies, and requires writing the dependency `.o` into each target's prerequisites.
- Write the object-rule targets and prerequisites **in a form resolvable to a literal `.o`/`.mod` basename**. **For an out-of-source build (`$(OBJDIR)` override), when a build-rule target is prefixed `$(OBJDIR)/` (e.g. `$(OBJDIR)/foo.o:`), the prerequisite consuming it must carry the same `$(OBJDIR)/` prefix (or a variable expanding to it). A bare `foo.o`/`foo.mod` becomes, under override, a target with no rule, and `make -j` stops with `No rule to make target`** (post_generate detects the prefix mismatch). For in-source-only rules, keep both targets and prerequisites bare. A `$(VAR)` prerequisite is allowed when the variable is defined **before the rule** (a forward reference expands empty → missing dependency); see `docs/RUNBOOK.md` §1-2-1.
- The `src/Makefile` must not cause a failure due to a missing dependency in a parallel build (e.g. `make -j 4`).
- **Out-of-source output contract (`build_system=make`):** the `src/Makefile` parameterizes `OBJDIR ?= .` / `BINDIR ?= .` / `RUNDIR ?= .` **and `BIN ?= <spec_id>_runner`** with `?=` defaults (`BIN` must be `?=` so Build/`Validate.execute` impose `<spec_id>_runner` — see [phase_03_build.md](../../../workflow/phases/phase_03_build.md)). Object/module go to `$(OBJDIR)` (`gfortran` uses `-J$(OBJDIR)` / `-I$(OBJDIR)`), the execution binary to `$(BINDIR)/$(BIN)`, and `test`/`check` output under `$(RUNDIR)`. The `test`/`check` target also declares `SPEC ?=` and `CASES ?=` (`?=` overridable) and invokes the runner as `$(BINDIR)/$(BIN) --cases $(SPEC) $(CASES)` so `Validate.execute`'s make-test re-run matches `run_program`'s argv (`Validate.execute` imposes the authoritative `SPEC`/`CASES` via the make-test env; the `?=` defaults — `SPEC ?= spec.ir.yaml` and `CASES ?= <all case_ids>` — keep a local `make all test` runnable standalone). The generated `src/` stays pristine (only the MCP audit log); `Build` overrides put the object in a per-run tmp and the exe in `binary/<binary_id>/bin/`. The `?=` default `.` keeps a local plain `make` in-source.

## 2. The quality-check target

- For a compiled `toolchain.language` (its language backend declares `COMPILED`, `registry.is_compiled_language`), a `test` or `check` target must be defined in `source/<source_id>/src/Makefile`. On absence, it is a `Generate fail`. The relevant target references the existing binary in `$(BINDIR)` with a **non-relinking** guard that fails closed when the binary is absent — `test -x $(BINDIR)/$(BIN) || { echo "error: $(BINDIR)/$(BIN) not built; run 'make all' first" >&2; exit 1; }` — and **must not** invoke `$(MAKE)` in the guard. Relinking inside `Validate.execute` would rebuild the certified binary from the quality-check re-run, turning a mere binary-name/availability mismatch into a silently different artifact; the fail-closed guard instead yields a clean retryable `make test` failure. For local use, run `make all test` (the `?=` in-source defaults are unchanged). The target generates the output destination with `mkdir -p $(RUNDIR)` (and the `raw/` required subdirectories the runner writes) **before** `cd $(RUNDIR)`, then runs the runner as `$(BINDIR)/$(BIN) --cases $(SPEC) $(CASES)` and confines the run output under `$(RUNDIR)`. The `--cases $(SPEC) $(CASES)` argv is **required**: the runner consumes its case set from `--cases` (and aborts without it), and `Validate.execute` imposes the same `SPEC`/`CASES` `run_program` uses so the make-test re-run's diagnostics match — a bare `$(BINDIR)/$(BIN)` makes the make-test candidate emit no `diagnostics.json` and fails `quality_check` (`post_generate` flags a `test`/`check` recipe that runs the binary without `--cases`). Because `$(RUNDIR)` can point to a not-yet-created run node dir, omitting `mkdir -p` makes `cd` fail.
