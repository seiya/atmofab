# Launch Prompt Reference

Human-facing reference for the conductor's launch-prompt render path. The **machine-parsed
templates** live as plain-text files under [`tools/prompt_templates/`](../../tools/prompt_templates/),
one `workshop_*.txt` per `(step, substep)` and declared shape plus three repair templates, all of a
`workshop leaf` — this document holds the non-parsed reference material around them.

The render path: the conductor supplies the launch-request parameters; `record-launch` renders the
prompt from `tools/prompt_templates/` (substituting the `<...>` placeholders and composing the target's
prompt fragments; the host-resolved `pure_context` documents are `seed` files of the leaf's tree, not
prompt text) and returns the rendered `launch_prompt_text`, which the conductor passes to the leaf on
its stdin. `tools/workflow_conductor.py:build_launch_request` reproduces the
same payload field-for-field.

**Two sections stood here until Z4 ([issue #171](https://github.com/seiya/atmofab/issues/171)) and are
deleted with the agentic leaf.** The *phase ↔ skill correspondence table* mapped each `(step, substep)`
to the `SKILL` its leaf was told to read: no leaf reads a `SKILL`, and the five phase `SKILL`s are
deleted. The *substep ↔ allowed validator gate correspondence table* canonicalized which
`validate_pipeline_semantics --stage` invocation a launch prompt body could state, enforced by a scan
of the rendered text: no leaf states a gate call or invokes one — every
gate is run by the conductor in its own process, and `docs/workflow/phases/phase_0{1,2,4}_*.md` are
canonical for which deterministic substep runs which stage. The *usage contract of `allowed_tmp_root`*
went the same way: no launch prompt names a temporary root.

#### Workshop leaf launch prompt (`leaf_mode = "workshop"`)

Every `LLM` leaf is a `workshop leaf` since [issue #534](https://github.com/seiya/atmofab/issues/534) PR-J4-b (`docs/ORCHESTRATION.md` §workshop leaf is canonical). Its prompt is rendered, on `Generate.generate`, from `workshop_generate_generate.txt` (`m3c`) or `workshop_generate_generate_harness.txt` (`harness`), its repair turns from `workshop_bundle_repair.txt`; on `Compile.generate`, from `workshop_compile_generate.txt`, its repair turns from `workshop_ir_repair.txt`; as the READING kind of a judging substep, from `workshop_compile_verify.txt`, `workshop_generate_verify.txt` (`m3c`) / `workshop_generate_verify_harness.txt` (`harness`) or `workshop_validate_judge.txt`, its repair turns from `workshop_verdict_repair.txt`; and, for the `escalate` diagnostician (a reading leaf since PR-J4-a), from `workshop_escalate_diagnose.txt` (one launch, no repair turn; its output file `directive.json`, its seed `diagnosis.json`). A repair template's slots are `<repair_scope>`, `<findings>`, `<tool_surface>` and `<launch_body>`. `_leaf_repair_template_name` selects the repair template: the verdict repair on a reading pair whatever its step, otherwise by `step`. Each prompt opens with the sentinel `Workshop leaf turn (host-seeded work tree)` (`leaf_contract.WORKSHOP_PROMPT_SENTINEL`, imported — not copy-pasted — by `orchestration_runtime.py` and `validate_pipeline_semantics.py`), anchored at line 0; a request and a prompt that disagree on it, in either direction, are refused. Its identity is the reduced marker set below:

| workshop launch marker | note |
| --- | --- |
| `Workshop leaf turn (host-seeded work tree)` | sentinel; MUST be line 0 (anchored `startswith`). |
| `Target node_key:` / `Target step:` / `Target substep:` | identity, each with the request's value. |
| `orchestration_id:` / `agent_run_id:` | ids. |
| `prompt_contract_version:` | must equal `leaf_contract.LEAF_PROMPT_CONTRACT_VERSION` exactly — the one leaf contract version since PR-J4-b (named `PURE_PROMPT_CONTRACT_VERSION` until PR-J4-d). Its value keeps the pure-era form `pure-84`, because a new value is a contract change; the next bump writes `leaf-85`. |

The launch request is built by `build_launch_request(pure_leaf=True)` — the request shape the pure leaf introduced, whose fields keep the `pure_` prefix (next section) — and carries `leaf_mode: workshop`, that contract version, `workshop_lineage_id` and `workshop_provider`. `_validate_leaf_launch_request_payload` accepts `workshop` as the one `leaf_mode` and a pair of `WORKSHOP_LAUNCH_PAIRS`, and requires the pair's `pure_context` keys on a cold launch; a warm repair, whose lineage already holds its seeds, may omit them. The persona line of every workshop template holds a `<tool_surface>` placeholder, which the renderer fills from `leaf_contract.WORKSHOP_TOOL_SURFACE_TEXT[workshop_provider]` on a producing pair and from `leaf_contract.WORKSHOP_READER_TOOL_SURFACE_TEXT[workshop_provider]` (a row for each of the four providers — one text for both HTTP providers — each carrying its transport's paging rule) on a reading pair, the one sentence of the contract that differs by transport; a provider with no row there is a named `ValueError` at render and is refused by `_validate_leaf_launch_request_payload`. The body states a work-tree contract and the substep's wrapper operations (five on `Generate.generate`, `check_ir` on `Compile.generate`, none on a reading pair, whose contract names its one output file at the tree root, `verdict.json`, `review.json` or `directive.json`, and tells the leaf to read the whole of what it judges; how a long read is paged is the reader row's, because it differs by transport), then the output contract and the authoring rules (`tools/tests/test_workshop_producer.py` and `tools/tests/test_workshop_reviewer.py` pin them). No document is inlined: each is named by its `seed` file in the tree, a reading template also naming the document key beside it, which is what `Validate.judge`'s `evidence_refs` cite; the certified sibling exemplar (R5), when the host found one, is the seed `EXEMPLAR.md` of a `Generate.generate` tree.

A repair turn carries the findings in the data-only fence below. A cold repair turn runs in a fresh lineage seeded from the prior lineage's snapshot, the document under repair among its files, and re-states the whole launch body after the findings (`orchestration_runtime._leaf_launch_body`: every paragraph between the persona line and the identity block, in template order; issue #510), together with the provider's `<tool_surface>` row, which the body, cut after the persona line, does not carry; a warm one carries the findings alone. `<repair_scope>` is filled only for the verdict-bearing pairs (`orchestration_runtime.PURE_VERDICT_PAIRS`: the two `verify` pairs and `validate.judge`) and is empty for a producer: it is `PURE_REPAIR_SCOPE_PARAGRAPH`, or, on a codex cut-read repair — `repair_reason: workshop_cut_read_repair`, [issue #547](https://github.com/seiya/atmofab/issues/547) — `WORKSHOP_CUT_READ_SCOPE_PARAGRAPH`, which is about the leaf's reading and is used on any pair. For a verdict every repairable class is a violation of the document's SHAPE, and the schema's joint invariant couples the conclusion to the evidence, so the paragraph states the invariant in BOTH directions: supply the evidence a `fail` is missing, or record the `fail` the evidence already listed calls for; what is forbidden is the dishonest edit — dropping a finding that was made, or recording a conclusion that was not reached. It is a SLOT and not a shared sentence because a producer's repair legitimately changes what its document says (`pure-41` measured one persona-neutral sentence making two reviewer routes worse than saying nothing).

**gate correspondence:** no leaf invokes a validator gate. Every gate is run by the conductor in its own process (`docs/workflow/phases/phase_0{1,2,4}_*.md`). A producing leaf's wrapper operations are feedback, not gates: `check_ir` runs the `Compile.static` validators over a scratch IR directory outside the tree, and the five `Generate.generate` operations call the build-runtime library; the host's own substeps over the lineage's snapshot are the authority.

**record-launch artifacts:** a workshop launch writes the launch record (`launches/<arid>.*`), the session-run-index row, the agent_graph edge and the active-child markers. A CLI launch also writes the lineage's `bwrap` profile — `leaf_mode: workshop`, `readonly: false`, `workdir` its tree, the lineage's `config/` and `tree/` as its rw binds beside its two scratch roots, `write_roots: []` (`build_lineage_bwrap_profile`, which keeps the name of the read-only profile it replaced) — and that profile is the one document about the launch that decides anything, because `bwrap` enforces it. An HTTP launch runs in the conductor's process with no profile; its response names its lineage home and its tool surface instead. `validate_pipeline_semantics`' launch-record sweep re-checks request-vs-prompt sentinel agreement, the reduced marker set, the profile's shape (or, on HTTP, `_http_workshop_record_violations`), and the terminal row's `output_refs == []`.

#### Launch-request context documents and fragments

The host-resolved `pure_context` documents each `(step, substep)` requires are the single source `PURE_CONTEXT_REQUIRED_KEYS` (`orchestration_runtime.py`); a cold launch missing one is rejected at `_validate_leaf_launch_request_payload`. Each reaches the leaf as a `seed` file of its tree (a reading template also names its document key beside it). For `(compile, generate)` they are `controlled_spec_document`, `tests_document`, `deps_document`, `profile_spec_document` (the `controlled_spec.md` of each `profile` this node ADOPTS — which profiles, and at which version, is read from the sidecar's `profiles` record, not re-derived from `deps.yaml` — or the host's fixed sentence when it adopts none), `dependency_graph_document` (the host-derived closure, which the leaf READS and must not copy into the IR; since issue #175 it also carries the `profiles` record, which is where the leaf's `direct_deps` and its per-case `profile_selection` both come from), `phase_contract_document` (`docs/workflow/phases/phase_01_compile.md` in full), `ir_algorithm_example_document` and `ir_algorithm_2d_example_document` (the two `docs/examples/spec_ir_algorithm*` reference forms), and `checks_module_contract_document` (the language-neutral §1-4 slice of `docs/workflow/CHECKS_MODULE_CONTRACT.md`; Compile is target-free, so it is shown none of the language binding the generate reviewer also gets). The compile producer is shown no target: until R4-a PR-3 (issue #284) it also carried `impl_defaults_schema_document` (the IR knob-name schema) and `toolchain_document` (the admissible `(language, build_system)` pairs), both deleted with the IR's `impl_defaults` section. For `(compile, verify)` they are `controlled_spec_document`, `tests_document`, `deps_document`, `ir_document` (the IR under review), `dependency_surface_document` (`<ir_ref>/dependency_surface.json` verbatim: each component dependency's published operation names and, since issue #486, its certified `IR`'s `public_api` `signatures` / `interfaces` / `module_parameters` — the producer receives the same facts through the rendered `<dependency_facts>` block instead), `phase_contract_document`, and the two example documents. The compile reviewer takes its severity rubric from the phase document it already carries in full, so it has no separate rubric slice. For `(generate, generate)` on the DEFAULT (m3c) shape they are `harness_capabilities`, `target_profile`, `ir_document`, `tests_document`, and `runner_document` — the last being the host-rendered runner source (`bundle_facts.runner_basename`) placed verbatim, because it is the consumer of the checks-module ABI the producer must author against and the producer is not handed `docs/workflow/CHECKS_MODULE_CONTRACT.md` (`docs/design/deterministic_followups.md`, Z2 defect D). The producer does NOT carry `controlled_spec_document`: the `pure-5` interim carve-out that inlined it (to close a producer-blind / checker-sighted asymmetry against a thin IR roll) was **removed at `pure-10`** once the `compile` side began guaranteeing IR self-sufficiency (the strengthened lowering rule + the deterministic `Compile.static` local-op lowering presence floor; `docs/workflow/phases/phase_02_generate.md` §Generate-executor, [issue #181](https://github.com/seiya/atmofab/issues/181#issuecomment-5559625628)). `(generate, verify)` carries `controlled_spec_document` by design (the reviewer verifies against it) and `target_profile` (the whole target profile, the same document the producer sees, against which G6 judges the bundle's `target_lowering_plan` and the source), but NOT `runner_document`: the deterministic layer owns the ABI and the reviewer is semantics-only, judging the bundle against the distilled **G1-G7** review checklist in its static prefix. Since `pure-24` it also carries `checks_module_contract_document` — the `## 1.`-`## 4.` slice of `docs/workflow/CHECKS_MODULE_CONTRACT.md` (`workflow_conductor._checks_contract_abi_sections`), followed since `pure-50` by the same slice of the target language's binding of it, `docs/backends/language/<language>/CHECKS_ABI.md`, read through the language backend's `checks_abi` capability (issue #289) — which the template's scope paragraph makes the authority for what the runner does with each callback's result; §5 of either is excluded (the neutral §5 is a pointer, the binding's is the deterministic legality/gate section the reviewer is told not to re-check; issue #142). A binding the target language does not declare, or cannot be read, fails the substep closed as `pure_checks_abi_binding_unavailable` / `pure_checks_abi_binding_missing`, and one whose section anchor is gone as `pure_checks_contract_document_unsliceable`. Like the four node artifacts (which degraded to `""` until issue #467 and now raise `pure_<controlled_spec|tests|ir|bundle>_document_missing`), an unreadable or unsliceable contract fails the substep closed before any leaf is spawned, as `pure_checks_contract_document_missing` (absent or undecodable) or `pure_checks_contract_document_unsliceable` (readable, but an anchor is gone), recovered by the caller into a `pure_context_assembly_failed` transport outcome. Both names reach the operator only through the run log and that outcome, so they are spelled here: the repair is to restore the document and `--resume`. Since `pure-25` it also carries `severity_rubric_document` — the `#### Severity of a finding` subsection of `docs/workflow/phases/phase_02_generate.md` §2-2 (`workflow_conductor._generate_verify_severity_rubric_section`), which is the sole rule for the `issue_severity` a verdict carries; G1-G7 are excluded because the template already states them (issue #143). It has the same non-degrading disposition and the same two operator-facing names in the same shape, `pure_severity_rubric_document_missing` (absent or undecodable; restore the document and `--resume`) and `pure_severity_rubric_document_unsliceable` — whose causes are NOT the checks pair's "an anchor is gone": the rubric must be the LAST subsection of §2-2, so it also fires when both anchors are intact and a subsection was added after the rubric, or when the `## On-failure behavior` heading line changed at all — the terminator is matched exactly, so an appended word is a rename. The raised message names which of the two it found; the repair is to restore the document's shape and `--resume`. The rubric's text was narrowed at `pure-26` and again at `pure-27`. For each `(<phase>, diagnose)` pair the single key is `diagnosis_document` — the host's JSON composition of the failed node and phase, the failed substeps' `agent_run_id`s, the workflow mode, and the CONTENT of the failure artifacts it could read, each artifact budgeted individually (`_bounded_context_json`) so the failed phase's own evidence gets the large slices and none is dropped. The diagnostician reads nothing else: its persona, its directive schema and its rollback / severity criteria are the template's static body. For `(validate, judge)` there are eleven keys: `tests_document` and `io_contract_document` (the judge's two canonical sources — the IR's `io_contract` section alone, `yaml.safe_dump`ed, never the 52 KB IR in full), `runner_output_contract_document` (the §1 + §3 slice of `docs/workflow/RUNNER_OUTPUT_CONTRACT.md` — `workflow_conductor._runner_output_contract_sections`; §2, §4 and §5 are excluded because they are `Validate.execute`'s deliverable gate and the deterministic layer), the run's own `diagnostics_document`, `verdict_document`, `perf_document`, `trial_meta_document` and `quality_check_document`, the `binary_meta_document` / `source_meta_document` the agentic judge force-read, and `raw_evidence_excerpt_document` — the host-computed bounded summary of `raw/` (`tools/raw_evidence_excerpt.py`), which is the judge's whole view of the primary evidence because `raw/` is 13 MB of float arrays. Canonical for what that excerpt contains: `docs/workflow/phases/phase_04_validate.md` §4-2-1. EVERY judge document raises rather than degrading to `""`, and the REASON is not the one an earlier version of this paragraph gave: a blank value does NOT reach the leaf, because `_validate_leaf_launch_request_payload` counts a whitespace-only `pure_context` value as missing and raises. What degrading buys is a refusal one frame too LATE — a `ValueError` out of `record_launch`, escaping the reviewer loop's named `pure_context_assembly_failed` branch and aborting the conductor instead, which is issue #168's recorded shape. Raising at assembly time keeps the named outcome. The names, spelled here for the same reason the `compile.verify` pair's are (they reach an operator only through the run log and that outcome): `pure_<key>_missing` for each of the nine file-backed documents; `pure_io_contract_document_missing` for a DIFFERENT condition — the IR is readable but declares no `io_contract`; `pure_io_contract_document_unreadable` when it does not parse as YAML; and `pure_runner_output_contract_document_unsliceable` when the contract is readable but a section anchor is gone. The repair for all of them is to restore the artifact and `--resume`. A cold repair runs in a fresh lineage whose tree holds the same seeds, and re-states the launch body, which has no document slot.

Since `pure-50` a `generate` launch request also carries **`pure_language`** (issue #289, R4-b PR-2): the target profile's `toolchain.language`, set by the conductor on a `generate` launch only (`Conductor._leaf_language`; Compile is target-free and the judge reads output documents). All four `generate` templates mark the places a language's rules go with `{{language:<name>}}`, and `orchestration_runtime._leaf_launch_template` composes each marker with the target language's fragment of that name (`prompt_fragments`, `tools/prompt_templates/backends/language/<language>/<template>.txt`) BEFORE any `<key>` substitution, so the cold launch and the cold repair's re-stated launch body read the composed text. The fragments are host-authored instructions, so they are spliced into the prompt rather than carried as `pure_context` seeds. A template with a marker and a request with no `pure_language`, a language that declares no `prompt_fragments`, and a marker the language defines no fragment for are each a named `ValueError` at render; a non-string or blank `pure_language` is refused at `_validate_leaf_launch_request_payload`.

Since R4-c PR-2 (issue #316; `pure-52`, re-pinned in place) a `generate` launch request also carries **`pure_parallel`**: the target profile's `parallel.backend`, set by the conductor on a `generate` launch only (`Conductor._leaf_parallel`). Each of the two default-shape templates places a `{{parallel:<name>}}` marker right after one of its `{{language:<name>}}` markers, and `_leaf_launch_template` composes it after the language's, from the parallel backend's fragment of that name (`prompt_fragments` on the `parallel` axis, `tools/prompt_templates/backends/parallel/<backend_id>/<template>.txt`). One rule differs from the language's: a parallel backend that declares no `prompt_fragments` composes every marker to the empty string, because a parallel model's text is a rule added for the model whose gate enforces it. A template with a marker and a request with no `pure_parallel`, a value the registry has no record for, and a declaring backend with no fragment file or no section for a marker are each a named `ValueError` at render; a non-string or blank `pure_parallel` is refused at `_validate_leaf_launch_request_payload`.

Since `pure-37` a launch request may also carry a **`pure_shape`** (issue #169), which selects both the template and the required-key set: the vocabulary is `orchestration_runtime.PURE_LAUNCH_SHAPES` and the sets are `PURE_CONTEXT_REQUIRED_KEYS_BY_SHAPE`, keyed by `(step, substep, shape)`, with the table above serving a request that declares none. A value outside the vocabulary, a non-string or blank one, and a shape declared on a pair the by-shape table does not carry are each refused at `_validate_leaf_launch_request_payload` rather than falling back to the default — the shape decides which admissibility rules the returned document is judged against. One non-default shape exists, and it is a bundle shape: `harness`, an `infrastructure` self-test whose leaf authors the executable entry itself. Its `(generate, generate)` keys are `harness_capabilities`, `target_profile`, `ir_document`, `tests_document`, `runner_output_contract_document` (`docs/workflow/RUNNER_OUTPUT_CONTRACT.md` in FULL — a leaf that writes the program reads every section, where the judge that only reads its output is shown two — followed since `pure-50` by the target language's runner-output binding, `docs/backends/language/<language>/RUNNER_OUTPUT.md`, read through `prompt_fragments`; `pure_runner_output_binding_unavailable` / `pure_runner_output_binding_missing` when it cannot be), `gate_guards_document` (§5 of the target language's checks-ABI binding `docs/backends/language/<language>/CHECKS_ABI.md` since `pure-50` — §5 of `docs/workflow/CHECKS_MODULE_CONTRACT.md` before it — `workflow_conductor._checks_contract_gate_guards_section`) and `lint_rules_document` — the static lint check's DECLARED RULE SET, by code and rule name, rendered by the linter BACKEND the node's language resolves to (`lint_rules_document` on the module `capability_module("linter", <preset>, "lint")` returns, the preset from the same `registry.linter_for_language` answer `_gate_lint_check` uses). It comes from the backend and not from the template because the rule set is that backend's knowledge and a `neutral core` template may not carry it (`docs/BACKEND_BOUNDARY.md`); §5 states the obligations whose IDIOM this repository fixes, and measurement showed it states only three of the seven codes this leaf must satisfy, so the two are inlined together and rule (11) holds the leaf to both. Its failures are named `pure_lint_rules_document_unavailable` — no lint preset for the language, a preset whose package does not claim the `lint` job, a backend that renders no rule set, or an empty one — and the repair is a preflight/backend problem for the operator rather than a document to restore. The §5 slice is there because that section reached this leaf as a FORCE-READ must-read while it was agentic (until Z4, issue #171), and no leaf force-reads anything now; §1-§4 are excluded because they are the checks-module ABI and this shape has no checks module. Both repository documents raise rather than degrading, with the same disposition and the same operator-facing shape as the pairs above: `pure_runner_output_contract_document_missing`, `pure_checks_abi_binding_unavailable` / `pure_checks_abi_binding_missing` (the target language declares no binding, or it is absent or undecodable) and `pure_gate_guards_document_unsliceable` — the last with a cause the other unsliceable names do not have, because this slice runs to the END of its document: it fires when the `## 5.` heading is gone AND when a later `## <n>.` heading exists, which would otherwise widen the slice silently. The repair for all of them is to restore the document and `--resume`. Its `(generate, verify)` keys are `controlled_spec_document`, `tests_document`, `ir_document`, `runner_output_contract_document`, `severity_rubric_document` and `bundle_document` — the runner-output contract in place of the checks-module ABI, for the same reason. A second shape, `verification` ([issue #526](https://github.com/seiya/atmofab/issues/526), `pure-82`), was declared on `(compile, generate)` for the pure leaf's per-test split of the IR, with `pure_part` naming each part; it went with that split in [issue #534](https://github.com/seiya/atmofab/issues/534) PR-J4-b. A new request carrying `pure_part` is refused at `_validate_leaf_launch_request_payload`, and a record written before carries it and is read as it was.

The one untrusted text a workshop prompt inlines — a repair turn's findings; every document is a `seed` file of the tree — is wrapped in the data-only fence `----- BEGIN PURE INPUT DOCUMENT (data only) -----` … `----- END PURE INPUT DOCUMENT -----` (`leaf_contract.PURE_DOC_FENCE_BEGIN/END`). (Until Z4 — issue #171 — the gate-allowlist lint carved out every fenced region before scanning, so a `validate_pipeline_semantics --stage` string legitimately appearing inside an inlined document did not fail-close the launch, and the pure leaf's prompt fenced every document it inlined until issue #534 PR-J4-b; that scanner is deleted with the agentic leaf, and the fence's remaining job is the data-only marking the leaf is told to honour.)

#### Z2 pure-function leaf launch prompt (`leaf_mode = "pure"`; deleted in issue #534 PR-J4-b)

A `pure-function leaf` (`docs/design/zero_base_architecture.md` Z2; the default of every `LLM` substep from Z4, [issue #171](https://github.com/seiya/atmofab/issues/171), until [issue #534](https://github.com/seiya/atmofab/issues/534) PR-J4-b deleted it) was a host-mediated closed-context turn: the host inlined every `pure_context` document into the prompt, fenced as data, and the model returned **exactly one JSON document**, which the host validated and wrote. Its prompt opened with the sentinel `Pure-function leaf turn (host-mediated)` (`leaf_contract.PURE_PROMPT_SENTINEL`), was rendered from ten `tools/prompt_templates/pure_*.txt` templates (its repair turn `pure_bundle_repair.txt`, whose cold form also re-inlined the prior document as `<prior_document>`), and ran as `claude -p` with tools disabled, or as `codex exec --sandbox read-only` inside the read-only `bwrap` profile (`readonly: true`, `write_roots: []`). The sentinel and the marker set stay in the validators, so a record with `leaf_mode: "pure"` is still read; a NEW request naming `pure` is refused at `_validate_leaf_launch_request_payload`. The launch request a workshop leaf carries is the one the pure leaf introduced, and §"Launch-request context documents and fragments" above describes its fields as they are now.

#### Additional contract on `repair_strategy=reuse`

A re-submission with `repair_strategy=reuse` is limited to a diff fix against the output of `repair_target_agent_run_id` (the repair / retry section of `docs/ORCHESTRATION.md` is the canonical source): the leaf returns its document and the host writes what it accepts, as for any substep. `record-launch` requires a non-empty `repair_target_agent_run_id` and `repair_reason` on every `reuse` / `restart` request.
