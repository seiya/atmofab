# Z4: retirement of the authoring-side enforcement complex

Status: **implemented, awaiting the billed completion run** (PR-1 [#218](https://github.com/seiya/atmofab/pull/218) merged 2026-09-12 as `71ffd18b`; PR-2 [#219](https://github.com/seiya/atmofab/pull/219) merged 2026-09-13 as `2a3a8547`). The record is [issue #171](https://github.com/seiya/atmofab/issues/171): its two 2026-09-12 comments hold the implementation plan and the option decision; the two pull request descriptions hold each stage's review loop and measurements. This note is the in-repository record of the decisions the issue did not make, the stage structure, and what the completion run has to show. It is the successor of `deterministic_followups.md` for this subject, which is frozen ([issue #181](https://github.com/seiya/atmofab/issues/181)) and takes no new entry.

## Purpose

Z4 is item 4 of the Z-series in `zero_base_architecture.md` §Migration items: once no leaf holds a shell inside the repository, delete the capability / manifest / hook / preflight / contract-document complex that existed to make such a leaf safe and observable. The premise it rests on is `AGENTS.md` §Development premises: the defended class is the `leaf shortcut`, and a mechanism that bounds an actor which no longer exists defends nothing. The retirement is item 4 of the simplification program's sequenced list (`simplification_program.md` §Sequenced), the last of the pure-leaf migration items.

## Scope

What a launch is after Z4, and what that made dead:

- A launch has exactly two shapes. **PURE**: `claude -p --safe-mode --tools "" --strict-mcp-config --disable-slash-commands --output-format json` (`tools/pure_leaf.py::pure_leaf_flags`), or the `codex_cli` approximation — `codex exec --sandbox read-only` with `--output-schema`, tool-bearing inside a read-only `bwrap` profile — or an HTTP provider with no process at all. The host inlines a closed context into the prompt, the model returns one JSON document, and the HOST writes every artifact. **DETERMINISTIC**: the conductor runs the substep in its own process. A request that is neither is refused (`_validate_launch_prompt_text`, `node_has_no_bundle_shape`). `docs/ORCHESTRATION.md` §pure-function leaf is canonical for the contract.
- Deleted with the agentic leaf (PR-1): the agentic loop arm and `leaf_command` arm, the three agentic prompt templates and their must-read assembly, the five phase `SKILL`s and `docs/AGENT_CONTRACT.md`, the leaf hook layer (`tools/hooks/cli.py`, `tools/hooks/adapters/`, `leaf_config/`), the claude private `CLAUDE_CONFIG_DIR` and the roster / MCP-registry / leaf-config probes, the codex hook, feature cache and hook preflight, and the `CAP_AGENTIC` capability in `tools/llm_config.py`.
- Deleted with the records nobody reads (PR-2): the capability document and `capability_token`, read / output manifests, access policies, access logs, `violations/` gating and `gates/`, the per-agent write baseline and terminal FS-diff, `run-gate` / `orchestration-read`, the read-write `bwrap` profile builder and file pins, `_write_roots_for_launch`, the validator arms over those records, the hook section of `tools/audit_orchestration.py`, and `tools/hooks/common.py` (what survived moved to `tools/operator_private_root.py`).
- Kept, and why: `build_readonly_bwrap_profile` / `render_bwrap_command`, `_prepare_codex_workflow_home`, `_probe_codex_backend` and the HTTP provider probe, because a pure leaf on a CLI provider is still a process and `no vendor lock-in` keeps the `codex_cli` provider ([issue #172](https://github.com/seiya/atmofab/issues/172) rejected); the DEV hook layer (`.claude/settings.json`, `.codex/hooks.json`, `tools/hooks/dev_cli.py` and its two modules), which governs the operator's own session; `tools/hooks/lint_evidence.py` and `syntax_evidence.py`, host-side helpers of the deterministic gates; `cleanup_committed/` and `_cleanup_agent_tmp_root`, which are tmp hygiene rather than enforcement.

Out of scope, each with its reason, is the issue's §Out of scope plus the plan's §8: `bwrap` on build / execute (A8 — `_run_command` in the build-runtime server is a bare `subprocess.run`, and adding a sandbox there is new work, not keeping one); the deterministic substep's record ceremony (`launches/`, `agent_runs` rows), which is orchestration record, not enforcement; `_pure_session_resumable` ([issue #177](https://github.com/seiya/atmofab/issues/177)); `--resume` of an orchestration recorded before Z4, which is not supported (its `capabilities/`, manifests and hook events are neither read nor validated).

## Decisions the issue did not make

The issue body left four judgments open. The 2026-09-12 plan decided them; three landed as planned and one was reversed by PR-1's review. Each is stated in the form it landed.

1. **The codex hook, feature cache and hook preflight are deleted** (reverses issue item 5's "keep `codex_feature.py`" and the sentence `simplification_program.md` §Sequenced item 4 carried). `tools/hooks/codex_feature.py`'s only reader was the leaf hook; the conductor's `_ensure_codex_feature_cache` existed to certify a cache for that reader; `leaf_config/codex/hooks.json` was the hook. With the reader gone all three are dead, and `ATMOFAB_REQUIRE_CODEX_HOOKS_FEATURE`, `codex_feature_check.json` and the `hooks_enabled` / `codex_project_hooks_validated` preflight checks went with them (`docs/ORCHESTRATION.md` items 38 and 46 keep their numbers and say so). The pure codex leaf's confinement is the read-only `bwrap` profile plus `--sandbox read-only` (`--config sandbox_mode="read-only"` on a resume) plus `--output-schema`, and the private `CODEX_HOME` keeps its `config.toml` `untrusted` marker so the DEV `.codex/hooks.json` cannot load into a leaf.
2. **The MCP gate is reduced to attribution** (issue item 6). Classification under `.claude/skills/atmofab-enforcement-change` rule 1-e: no LLM leaf can reach `mcp_servers/build_runtime_server.py` (a pure claude leaf passes `--tools ""` and `--strict-mcp-config`; the codex private home declares no MCP server; HTTP has no process), so the only callers were the conductor's in-process gates, each validating its own arguments against a capability file the same `record_launch` had written. A host checking its own record is a defense against the host, which the premises place out of scope; the blank in "the leaf gets closer to ___" does not fill. `orchestration_id` / `agent_run_id` stay as `command_log.jsonl` attribution, and `capability_token` is REFUSED as a retired argument rather than ignored, so a caller written against the old contract fails instead of being served as if the check passed. One validation mode remains for every caller (`env` override denylist, `target` / `extra_args` shape rules, one name set and one normaliser for both halves — `mcp_servers/README.md` is canonical). Its ceiling is stated there too: `run_program`'s `command` is caller-chosen argv, so these rules catch a mistake in the one command line this repository composes and confine no one.
3. **A deterministic in-process substep's launch records no sandbox** (`leaf_transport: "in_process"`, `sandbox_runtime: "none"`, `sandbox_enforced: false` on the RESPONSE, the same shape as the HTTP arm). A `bwrap` profile and a private home built for a process that never exists are a record of a confinement that never happened; `_launch_setting_surface` already refused the same false record on the settings side. This is what removed the last caller of `_prepare_claude_workflow_home` and `build_bwrap_profile`. The rejected alternative — giving a deterministic launch the read-only profile — would have kept a builder alive for the sake of a uniform-looking record.
4. **The pure codex leaf's read boundary is IN scope, and the plan's classification was wrong.** The plan (§6.6) had dropped it under rule 1-e on the ground that the prompt already gives the leaf the gate's rules. PR-1's round-1 review (the read-boundary finding) and its round-2 Codex pass reversed that: the prompt gives the leaf the RULES, the checkout gives it the CHECKER, and a leaf that can read `tools/validate_pipeline_semantics.py` can satisfy a presence floor's exact signal without doing the work the floor stands for; a VERIFY leaf that can read the PRODUCER's `dialogs/` for the run it is reviewing defeats a persona separation the code calls structural. What landed: `render_bwrap_command` overlays an empty tmpfs on `<repo>/workspace`, every `workspace_*/` archive and `releases/` (`_leaf_hidden_artifact_trees`, enumerated from disk) for a read-only profile, measured under real `bwrap`; that closes the named gains over run artifacts and certified sources. What remains open, HIGH, is `TODO.md`'s entry on the pure CODEX leaf's read boundary: `tools/`, `docs/` and `spec/` are still readable, closing them means binding only the launch's own necessities instead of the checkout, and that needs a measured codex launch under the narrowed profile, which this machine could not produce at the time (`codex` resolved to a volta shim that failed inside `bwrap`; issue #226 closed that launch blocker by binding the install root, and the measurement itself is issue #227). The claude pure leaf's closed context is structural (`--tools ""`) and unaffected.

## Stage structure and the order decision

The hook READS the record, the runtime WRITES it: PR-1 deleted the readers, PR-2 the writers, PR-3 records. Each stage swept the prose that cited what it deleted (`atmofab-enforcement-change` rule 3), and each stage's review closed before the next opened (`atmofab-review-loop` §Review target). Dead code at PR-1's tip (`build_bwrap_profile`, the record writers) was dead rather than broken.

**Option B was taken** (operator decision, issue #171 comment of 2026-09-12): PR-1 landed BEFORE the billed A/B of Z1 ([issue #168](https://github.com/seiya/atmofab/issues/168)) and Z3 ([issue #169](https://github.com/seiya/atmofab/issues/169)), which `zero_base_architecture.md` §Migration items Z4 ("each deletion lands with the migration that makes it dead, never ahead of it") and §Decision Criteria (billed A/B, "equal-or-better") would have had precede it. The ground: since #169 PR-3 every in-tree node dispatched every LLM substep to the pure loop by default, so the agentic path had no default caller; and a `git revert` of PR-1 and PR-2 restores it if the pure path proves worse. The cost: the agentic arm of the A/B cannot be re-run. What remains for comparison is the two recorded agentic baselines, `orch_20260904T135305Z_c2e771f9` (`component` `dynamics_advdiff_flux_1d_upwind_center2`) and `orch_20260905T013705Z_0e38fefa` (`shallow_water2d --with-deps`), and ONE billed run after PR-2 serves as Z1 / Z3 adoption evidence (compared against them) and as Z4's completion evidence at once.
