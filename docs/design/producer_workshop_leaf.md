This document extends `zero_base_architecture.md` and departs from three of its items (§Departures); it keeps the deterministic `conductor`, the host-owned evidence channel (A4 / Z6), the derivation-keyed store (Z5) and the `CodegenBundle` contract (Z0) as they stand. `docs/ORCHESTRATION.md` §workshop leaf is canonical for what is implemented; this note remains canonical for the decision and for the steps not yet taken. The term `workshop leaf` is defined in `docs/GLOSSARY.md`, whose `proposed` mark step 1 removed.

## Purpose

Decide which `LLM` `substep` keeps the `pure-function leaf` shape and which one changes to an agent working in a sandbox, state the sandbox each shape requires, state what the producer is shown and what that leaves unprotected, and state the evidence on which the change is adopted or declined.

## Scope

- The five `LLM` leaves `compile.generate`, `compile.verify`, `generate.generate`, `generate.verify`, `validate.judge`, and the `escalate` diagnostician.
- The sandbox of a leaf.
- Out of scope: the phase sequence, the gates, the verdict evaluator, the store, and the sandbox of the deterministic `Build` and `Validate.execute` substeps (§Not adopted). None of them changes under this note. The contract sentences the adopting pull request rewrites are listed in §Departures.

## Terms

- **`workshop leaf`**: an `LLM` agent that runs with a tool surface inside a host-prepared, host-confined work tree, and whose result is the final state of that tree. Defined in `docs/GLOSSARY.md`.
- **work tree**: the directory the host seeds for one `workshop leaf` lineage and the leaf writes into. It is not an artifact: no gate, no later `phase` and no other lineage reads it, and a warm repair of the same lineage is the only later reader.
- **lineage**: one `workshop leaf` session together with its work tree: the cold launch that started it plus every warm repair of it. The word is used as `codex home lineage` uses it (`docs/GLOSSARY.md`), and is distinct from `attempt`, which the glossary defines as one execution of a `phase`.
- **host-placed input**: a file the host places for a lineage and the snapshot never copies. Three kinds: a **seed** (one file per key of the producer's pure context, plus the dependency facts, the exemplar and the phase contract text the template carries, written into the tree before launch, §Seeding); a **derived control file** (what `derive` renders into the tree, §Tool surface); and the **staged closure** (the dependency closure's compiled objects and interface files, placed by the wrapper outside the tree, §Tool surface). The host's own copy is what every gate reads.
- **snapshot**: the host's copy of the work tree's final state into the producer's existing output contract (§Output files in the tree), taken after the leaf exits.
- **wrapper**: the host-side service through which a `workshop leaf` derives, compiles, lints, syntax-checks and runs. A tool call crosses the sandbox boundary to the conductor's process, which runs the build-runtime library (`tools/build_runtime.py`) under the lineage's own confinement (§Sandbox). No file of `tools/` is mounted into the leaf's sandbox. §Transport states how each provider's leaf reaches it.

## Premises

The premises of `AGENTS.md` §Development premises apply unchanged, and one operator-stated constraint of `zero_base_architecture.md` §Premises (its item 5) joins them. Three decide this note:

1. **A leaf is not malicious and takes shortcuts** (`AGENTS.md`). A hole is in scope when a leaf that takes it gets closer to reporting its `substep` done. A defense against the operator, who owns the machine, is out of scope.
2. **No vendor lock-in** (`AGENTS.md`). A change to the leaf model is complete only when it lands on every declared provider, the HTTP transports included.
3. **Cost per certified artifact is a design objective** (`zero_base_architecture.md` premise 5). The dominant term is output tokens: a leaf's wall clock is its model generation at a throughput floor of about 100 tok/s on Opus (`skills/workflow-timing-audit/SKILL.md`; an HTTP endpoint of the recorded corpus ran at 17.6 to 59.8 tok/s, `docs/ORCHESTRATION.md` §Leaf LLM configuration), and prompt caching reduces input cost only.

Four facts follow for the producing leaves.

- **A producer that must write a whole document in one reply gave up on a large node on one provider, and writes about 117k to 137k output tokens per reply on the other.** The give-up record is codex before the part split (issue #526). The claude records are the channel bundle at 116,854 output tokens in one reply (14.9 min recorded; 81,015 of the tokens are thinking, and the document itself is 67,135 bytes), and one reply that reached 136,714 output tokens and could not be parsed. One such reply alone exceeds the 100k output tokens per certified node that `zero_base_architecture.md` §Decision Criteria targets.
- **The part split pays the whole prompt per part.** It is a host-side decomposition of the work that an agent harness performs itself, and it does not shrink the prompt: each part is handed the whole input again, so the 6-part channel node pays 6 launch prompts — 98,636 to 110,311 input tokens each on codex for a first assembly, 119,965 to 227,121 for a second and 380,254 for a third assembly's core (the two codex rows); 125,590 to 253,890 prompt tokens each on claude — twice when `Compile.static` revokes the first assembly (the claude row: 2,807,009 tokens for one certified IR).
- **Every repair re-emits the whole document.** The repair contract on both the warm and the cold path is one complete corrected document (`tools/prompt_templates/pure_bundle_repair.txt`; `docs/ORCHESTRATION.md` §pure-function leaf; issue #510). A one-line gate finding against a bundle costs a whole-document reply again; the recorded warm repair of the channel bundle cost 39,145 output tokens.
- **A physics failure at `Validate.execute` leaves no tree to return to.** Both claude channel runs ended there, failing closed as `dev` mode does (`docs/workflow/phases/phase_04_validate.md`); neither was regenerated. Whatever route the next producer launch on that node takes — a `restart` directive in `prod`, or an operator's `--resume` after a fix — it pays the first-reply figure again, because the pure shape holds nothing of the previous attempt a producer may read.

One fact for the judging leaves: a judging leaf reads and decides, performs no search, and is the leaf on which the agentic shape measured ten times the cost of the pure shape. That measurement is of the agentic leaf Z4 deleted, not of the `workshop leaf` (§Design Policy).

One fact about what the producer is shown, and it is a fact about the CURRENT design: on an `m3c` node `generate.generate` is handed the whole `tests.md` (`tests_document`), the host-rendered runner (`runner_document`), the whole `spec.ir.yaml` with its `primary_predicates` and `test_predicates`, the target profile and the harness capabilities — the five keys of its pure context (`tools/workflow_conductor.py` `_build_pure_context`; `tools/tests/data/conductor_launch_requests/generate_generate.request.json`), plus the dependency facts and the exemplar the template carries; on the `harness` shape the keys are those of `_build_pure_harness_context` (no runner; the runner output contract, the gate guards and the lint rules instead). `compile.generate` is handed `tests.md` and `controlled_spec.md` as primary inputs. What no producer is shown is the host evaluator (`tools/verdict_evaluator.py`, `tools/primary_evidence.py`), the judge's excerpt policy, a dependency's certified SOURCE (the producer sees dependency facts only, `<dependency_facts>` in `tools/prompt_templates/pure_generate_generate.txt`), and every past artifact. The defense of the current design is therefore not secrecy of the judgment but host ownership of the evidence channel (A4, Z6): a leaf that reads every predicate and holds no write path to captured state gains nothing from reading them, and the one gain it keeps — registering state that fits the visible cases — is the accepted residual A4 names, accepted there on the ground that such a state is a harder defect to produce BY ERROR than checks that report pass.

## Design Policy

The leaf model is decided per role.

| role | leaves | shape | reason |
|---|---|---|---|
| judging | `compile.verify`, `generate.verify`, `validate.judge` | `pure-function leaf` by default; a READING `workshop leaf` on a `leaf: workshop` entry, adopted 2026-10-25 (step 3a) | reads and decides; an independent reviewer shares no context with the producer; the inline-everything prompt has a provider ceiling the channel node exceeds (below) |
| judging | `escalate` | `pure-function leaf`, unchanged | its prompt is bounded (`_bounded_context_json`), so it meets no ceiling and gains nothing from the shape |
| producing | `compile.generate`, `generate.generate` | `workshop leaf` | the one-reply shape gave up on a large node on one provider, writes 117k to 137k output tokens per reply on the other, pays the whole prompt per part, and re-emits whole documents on repair |

**Why the judging row moved.** It moved on the judge A/B of 2026-10-25 ([result](https://github.com/seiya/atmofab/issues/534#issuecomment-6392350241), [decision](https://github.com/seiya/atmofab/issues/534#issuecomment-6392781674); §Decision Criteria, judging leaves). The ground that kept the judges pure is the `Z3` measurement (`validate.judge` agentic 2,122,319 tokens / 396 s against pure 202,313 / 109 s). It measured the agentic leaf Z4 deleted — a leaf that read the repository and ran the gates — not the `workshop leaf`, whose seeded tree and bounded surface cut the PRODUCER's output tokens on both CLI providers (step 1 A/B, [issue #534 comment](https://github.com/seiya/atmofab/issues/534#issuecomment-6366969649); step 2 cost profiles). The pure shape inlines every document into one prompt, and that prompt has a provider ceiling: on the channel node `shallow_water2d_channel@0.2.5` the rendered pure prompts of one claude run were 839,905 characters (`compile.verify`) and 1,777,430 (`validate.judge`), and `codex_cli` refuses a turn above 1,048,576 characters (`input_too_large`, [issue #534 comment](https://github.com/seiya/atmofab/issues/534#issuecomment-6381040176)). The channel node therefore cannot certify on `codex_cli` under the pure judges, which premise 2 makes a defect.

**What the pure comparison cannot be.** A pure channel judge is one model turn. A reading judge pages the same documents through tool turns, each re-sending the growing context, so it takes longer and spends more on cache re-reads by construction (on the step-1 small node the workshop producer already cost 21 % more in `cost_usd` with 34 % fewer output tokens, [issue #534 comment](https://github.com/seiya/atmofab/issues/534#issuecomment-6366969649)). On `codex_cli` the channel node has no pure judge at all. The cost comparison is therefore a dearer judge against no judge on one provider and a ceiling on every other, and cost and wall clock are reported dimensions decided by the operator (§Decision Criteria, judging leaves), not decline conditions.

**The in-scope risk of a reading judge.** A pure judge is shown every item by the host; a reading judge chooses what it reads. Returning `pass` without reading is a `leaf shortcut` whose gain is a wrong certification, so the A/B measures detection of known defects on both arms, not only agreement and cost.

What is NOT adopted, and the rule that rejects it: an `LLM` that drives the phase loop, or that holds the gates, the evaluator or the verdict. The first is the $O(\text{turns}^2)$ cost in the baseline table; the second places what judges the result within reach of a leaf under a goal, which is the `leaf shortcut` class.

### `workshop leaf`

A `workshop leaf` replaces the one-reply document of a producing `substep`; it replaces nothing downstream of the producer.

- **Seeding.** The host writes into the work tree one file per key of the producer's pure context as it is rendered today, plus the dependency facts, the exemplar and the phase contract text the template carries. No other file is placed in the tree before launch, and nothing outside the host-placed inputs (§Terms) is reachable. The runner is a seed on an `m3c` node: `run_phase` renders it from the IR before any generate substep runs (`tools/workflow_conductor.py` `_write_runner`), and the leaf's compile reads the seeded copy while the host's `Build` reads the host's. Whether a producer should be shown less than today is a separate decision (§What the producer is shown).
- **Tool surface.** Read and write within the work tree, and the wrapper's five operations: `derive` (the Generate-time derivation the host performs on an accepted bundle — the build graph from `bundle.yaml`'s roles (`tools/codegen_bundle.py` `derive_build_graph`, applied by `tools/workflow_conductor.py` `_build_pure_bundle_graph`) and the control files rendered from it (`_render_pure_makefile_from_graph`) — applied to the tree as it stands, so it needs `bundle.yaml` to exist and refuses a tree without one); compile of the derived graph; `static lint`; `syntax check`; and execution of the built binary on inputs the leaf writes, the IR's declared cases included. The derived graph links the dependency closure — every closure member's certified model source and the target's harness (`_stage_dependency_sources`) — and the wrapper stages that closure as the STAGED CLOSURE: compiled objects and interface files it builds from the host's copies, placed outside the tree where only the wrapper's own runs (§Sandbox, second row) can read them. The leaf never reads a dependency's source, as today. The wrapper composes every build-runtime argument itself — the staged paths, the output directories, and for `run` the binary and the case file the leaf names, each resolved under the tree root and refused otherwise — so the type-only validation of `tools/build_runtime.py` keeps the premise issue #457 gave it (the caller composes `env`, `target` and `extra_args` from host constants); what the leaf chooses is the content of the tree. The lint and syntax results are feedback: the host's `Generate.gate` and `Compile.static` still run on the snapshot and are the authority, and a seed the leaf edited changes the feedback and nothing else.
- **Not on the surface.** The verdict evaluator (`tools/verdict_evaluator.py`, `tools/primary_evidence.py`), the gates, a dependency's source, every `workspace/` artifact of any other lineage, the CLI's session store (§Sandbox), `spec/`, `tools/` (the wrapper is a service, not a mount), `docs/`, `.git/`.
- **Output files in the tree.** `generate.generate` writes `bundle.yaml` at the tree root carrying every member the bundle schema requires (`spec/schema/generate/codegen_bundle.schema.json`) other than `files[].content`, which the snapshot reads from the files the manifest names. `compile.generate` writes `spec.ir.yaml` at the tree root, or, when it finds an input absent, self-contradictory or insufficient, `compile_fail.json` in the structured form the pure leaf returns today (`{input, where, what}`, with `input` validated against the admissible context keys, `docs/ORCHESTRATION.md` §pure-function leaf), which the snapshot treats as the `compile_declared_fail` exit under the same rules. A tree holding none of its output files is snapshotted as `workshop_tree_empty`, a failure category of the producer. When the lineage is still open (the leaf exited on its own), it is routed as a malformed bundle of the producer is today: a bounded warm repair on the same lineage, then a fresh attempt with `reuse` (`GENERATE_BUNDLE_FAILURE_ROUTING`, `docs/ORCHESTRATION.md` §Leaf LLM configuration). When a bound ended the lineage (§Bounds), the warm path has no lineage to return to, and the category takes the cold-`reuse` path of §Repair: a new lineage seeded from the snapshot plus the finding.
- **Hand-off.** The snapshot is validated under the existing contract and the existing gates run in the host's own process. Every artifact a later `phase` reads is host-written from the snapshot, as today.
- **Repair.** The directive selects the path, as `docs/ORCHESTRATION.md` §repair / retry defines it; what changes is what each path carries. **`reuse`, session continuable (warm)**: the gate finding is appended to the SAME session over the SAME work tree, and the leaf edits in place; a CLI provider continues its session as `warm_resume` does today, and the host tool-use loop holds the conversation in memory as `_run_http_leaf` does today. A cross-phase `reuse` reopen of the producer is this path when the lineage still exists. **`reuse`, session not continuable (cold reuse)**: a new lineage whose tree is seeded from the snapshot of the lineage being repaired plus the findings. **`restart`**: a new lineage seeded from the seed alone, with no snapshot and no findings, because a `restart` re-derives from scratch and reads none of the discarded attempt (`docs/ORCHESTRATION.md` §repair / retry; `deterministic_conductor.md` §Design). On no path does the leaf re-emit the whole document; the whole-document repair contract is retired for the producing leaves.
- **Independence of review.** A `workshop leaf` may use its harness's sub-agents internally; they share its tree and its surface. `generate.verify` and `compile.verify` run outside the producer's work tree — as a pure leaf, or as a reading `workshop leaf` in a lineage of their own whose id is their own cold launch's — launched by the host from the snapshot, sharing no session and no tree with the producer.
- **Record.** Under the host tool-use loop every request, response and tool call passes through the host and is recorded under the lineage, as the pure HTTP leaf's `http_response.txt` is today: the record is total by construction. Under a CLI harness the host records what the CLI emits (its result envelope and transcript), and `docs/ORCHESTRATION.md` §pure-function leaf already records that a CLI leaf's input is not a function of the host prompt alone. On either transport the wrapper writes `command_log.jsonl` under the lineage's record outside the tree — the host's own record of every build-runtime call, which the leaf cannot edit. Usage is recorded per turn, with the running-total trap of `TODO.md` (issue #281) resolved for each agentic transport before its first billed comparison.
- **Bounds.** A `workshop leaf` entry in `llm.yaml` carries two required fields with no default, for the reason `docs/ORCHESTRATION.md` §Leaf LLM configuration gives for `llm.yaml` itself: `max_wrapper_calls`, counted by the wrapper, which the host sees on every transport — at the cap it refuses further calls and the host terminates the leaf; and `lineage_timeout_s`, a wall-clock bound the host enforces across every launch of the lineage. On a CLI transport each launch keeps the per-process bound that exists today (`ATMOFAB_LEAF_TIMEOUT_SECONDS`, the process-group kill), and `lineage_timeout_s` is a second bound beside it; on the host tool-use loop it replaces the per-request `timeout_s` bound, which under a loop of requests bounds nothing. Both bounds are counted per lineage, both END the lineage, and in either case the tree is snapshotted as it stands. A CLI turn count is not the mechanism: measured 2026-10-22, `claude --help` (2.1.308) and `codex exec --help` (0.163.0) expose no turn bound. A READING `workshop leaf` (a judging substep, step 3a) is served no wrapper operation, so its entry states `lineage_timeout_s` alone and `max_wrapper_calls` is refused there (`docs/ORCHESTRATION.md` §Leaf LLM configuration).

### Transport

How a leaf reaches the wrapper is per provider.

- **HTTP providers.** The host tool-use loop (§Provider neutrality) runs in the conductor's process; a tool call is a function call. No leaf process exists.
- **CLI providers.** The only route either CLI offers to a custom tool is an MCP server: `claude --mcp-config` (2.1.308; `--tools` selects built-ins only) and codex's `mcp` configuration (0.163.0). Neither CLI accepts a Unix-socket transport (`claude mcp add --transport` takes `stdio`, `sse` or `http`; `codex mcp add` takes `--url` for a streamable HTTP server or a command for a stdio one), and a stdio server would be a file mounted into the sandbox. The wrapper is served by the conductor's process as a streamable-HTTP MCP endpoint on a loopback address inside the lineage's network namespace, one per lineage, and the leaf's CLI is configured to that endpoint alone (`--strict-mcp-config` on claude). The namespace's route set is therefore two addresses: the provider forwarder and the wrapper endpoint (§Sandbox). This returns the MCP transport issue #444 deleted, for the wrapper alone and as a host-served endpoint rather than a library inside the leaf's sandbox; §Departures names it. A claude `workshop leaf` cannot take `--safe-mode`, which starts with MCP servers disabled; what `--safe-mode` closed by launch shape (`CLAUDE.md`'s top paragraph: project instructions, skills, hooks) is closed instead by placement at cold launch — the checkout is an empty tmpfs so no project file exists to load, and the private per-lineage home (§Sandbox) is host-authored with no settings, skills or hooks in it — and by a read-only remount of every host-authored file of that home on every launch, the device the codex lineage home already uses for its `config.toml` (`tools/orchestration_runtime.py`). The leaf's working directory is the work tree, which the leaf writes; what the CLI loads from a leaf-written file under the tree or the home on a warm resume is undefined here and is measured by the adopting pull request. The flag set a claude `workshop leaf` keeps from `tools/pure_leaf.py::pure_leaf_flags` is `--restricted`, `--strict-mcp-config`, `--disable-slash-commands`, `--output-format json` and the host `--system-prompt`; it drops `--safe-mode`, and `--tools ""` becomes a `--tools` allowlist of the built-in file tools over the tree alone, whose names the adopting pull request states from the CLI it measures. The codex counterpart is the adopting pull request's to state from the CLI it measures.

### What the producer is shown

Two options; the first A/B runs under option S, and option W is the operator's decision, not decided by this note.

- **Option S (shown, as today).** The seed is the producer's current pure context. The residual, named on its own ground: a producer that can execute its binary on the IR's declared cases, read every predicate and read its own captured state can fit the state to the visible predicates by feedback and confirm the fit before hand-off. A4's acceptance of the fitted-state residual does not transfer, because A4 accepts it as a defect harder to produce by error, and under S it is produced by a goal-directed loop. What stands against it under S is `Generate.verify`'s rows G1 / G3 / G5 (`docs/workflow/phases/phase_02_generate.md` §2-2, judged by an `LLM` reviewer) and, on a `problem` node, the `Generate.gate` model gates of §2-1, none of which tests a state against anything but the visible cases. The route is `generate.generate` to snapshot to a passing verdict; the gain is a certified kernel correct on the declared cases and on nothing else. The A/B's choice of S is made with this gap named.
- **Option W (withheld).** The seed carries the IR with `io_contract.test_predicates[].pass_when` and `io_contract.primary_predicates` removed and `tests.md` removed, keeping `diagnostics_contract` (the check ids and verdict fields the runner must emit) and the case set. Undefined under this note and refused by it: which IR sections a producer needs to emit a conforming runner, and whether `Compile.generate` can be run under W at all (its primary input is `tests.md`). Adopting W is a phase-contract change (`docs/workflow/phases/phase_02_generate.md`) with its own review.
- **Held-out cases.** Deferred and undefined. Running host-derived cases at `Validate.execute` needs two things neither `docs/TESTS.md` nor `tools/primary_evidence.py` provides: a predicate scope for a case outside a predicate's `target_cases` (the grammar ranges over exactly those, `tools/primary_evidence.py` `_predicate_scope`), and a reference computed from the inputs rather than a band calibrated against one (`docs/TESTS.md` §Refinement judgment, §Symmetry pairs). No `tests.md` in the tree declares an admissible input range (enumerated 2026-10-22 over the 18 `spec/**/tests.md` with `os.walk`; 0 matches for an admissible-range statement). This note counts held-out cases as no defense.

### Sandbox

Three rows. Every row describes the LOCAL site; a remote `execution site` (`docs/ORCHESTRATION.md` §Execution sites) runs no `LLM` leaf.

| sandbox | holds | writable | network | technology |
|---|---|---|---|---|
| `workshop leaf`, CLI transport (the leaf process) | the work tree; the provider CLI read-only; a PRIVATE per-lineage config home holding the provider's credential material, its host-authored files remounted read-only | the work tree and the private home | the provider's endpoint set and the wrapper endpoint only | `bwrap` + a network namespace |
| the wrapper's runs (every transport): the toolchain, the lint tool, the built binary | the work tree; the toolchain and the staged closure read-only | the work tree | none | `bwrap`, run by the conductor's process |
| pure leaf, CLI transports | nothing (an empty tmpfs at the checkout path, as since issue #227); the CLI's config home read-write, as today | its two scratch roots and the CLI's config home | unrestricted today; the provider's endpoint set only under this note | `bwrap` |

A `workshop leaf` on an HTTP transport has no leaf process: the host tool-use loop runs in the conductor's process and the second row is its whole sandbox. The second row exists because the binary the wrapper runs is leaf-authored code: it is confined to exactly what the leaf is confined to, so nothing the leaf cannot reach through a tool becomes reachable through a program it wrote. Undefined and measured by the adopting pull request before the `rk4` row is the small-node arm: whether the launcher of a process-parallel target (`fortran_cpu_mpi`) runs under a network namespace with no interface up. The `Build` and `Validate.execute` of the SNAPSHOT stay where they are (§Not adopted).

The private home is required because a tool-bearing leaf can read what a tool-free one cannot: today the CLI's config home (`~/.claude` with `~/.claude.json`) is bound read-write into every claude leaf for auth and the session transcript (`tools/orchestration_runtime.py`, the rw bind its profile builder documents), and that home holds the transcripts of every other leaf of every orchestration under `~/.claude/projects/`. A `workshop leaf` with a read tool in that sandbox could read a sibling lineage's bundle, the reviewer's findings on its own previous attempt, or the attempt a `restart` discarded — each a past artifact read as input, the `leaf shortcut` `docs/workflow/WORKFLOW_CORE.md` forbids. The granularity is one home per lineage, because a warm repair resumes the session the lineage started (`--resume <arid> --fork-session`, `tools/pure_leaf.py`) and needs that transcript and no other: the codex lineage home of issue #245 is the shape — one `CODEX_HOME` per thread, holding a host-written `config.toml` and a placeholder over which the operator's `auth.json` is bound, with nothing copied. The claude counterpart is one `CLAUDE_CONFIG_DIR` per lineage, host-authored (§Transport); what the claude CLI needs in it beyond the bound credential file is undefined here and is measured by the adopting pull request (the per-orchestration home of issue #63 held a settings file and a credential placeholder over which the operator's credential file was bound, and is not this shape). The network rule applies to the first and third rows: a namespace whose only routes are a host-provided forwarder to the provider's endpoint set and, in the first row, the wrapper endpoint (§Transport), so that no leaf reaches an endpoint the host did not configure. The endpoint set of an HTTP entry is its `base_url`; the set of a CLI entry (the API host and whatever the CLI's auth refresh reaches) is undefined here and is the adopting pull request's to measure per CLI. It is a new requirement on the pure CLI leaf as well, whose profile today carries no network namespace (`tools/orchestration_runtime.py` `render_bwrap_command`), and it does not reverse the leaf-environment rule of issue #83 (`LEAF_ENV_NAMED_EXCLUSIONS`): the forwarder is reached by the namespace's route, not by a proxy variable.

Virtualization stronger than user-namespace containment (a VM, a user-space kernel) is not required, and the rule that declines it is premise 1: the holes a VM closes beyond `bwrap` are holes against the operator's machine, and a leaf gains nothing toward its verdict from any of them.

### Provider neutrality

A `workshop leaf` needs an agent loop. The CLI providers (`claude_cli`, `codex_cli`) carry one; the HTTP providers (`openai_compatible`, `anthropic_api`) carry none. The rule: the host owns a minimal tool-use loop in `tools/` with exactly the tool surface above (read, write, the wrapper's five operations), driven over each provider's tool-calling API, and every provider runs a `workshop leaf` through it or through its CLI harness with the same surface. A CLI harness's additional capabilities (sub-agents, context compaction) are permitted on top of that surface and are not required by any contract. Keeping the HTTP providers on the pure producer instead is rejected by premise 2: a leaf-model change is complete only when it lands on every declared provider.

The decisions: the rule is STRICT, any cut in the turn whether or not it was re-read, because re-reading a projection in full is not decidable; the repair is a cold launch from the seeds alone, as the unfinished-review re-run is, because a warm turn holds the cut texts and the conclusion drawn from them and a document left in the tree is accepted by a turn that reads nothing (round 1 reversed the plan's warm repair); a schema-valid `fail` is accepted with its count, because it certifies nothing; a cut read beside a malformed or missing document is the cut read; a read delegated to a sub-agent (codex's `collaboration` tools, which neither record of the launch shows) counts as a cut read; an unreadable rollout fails closed; only codex reading lineages are scanned (claude's `Read` says where it stopped; a producer's tree is gated; the HTTP loop serves its own reads). Not done: a per-test split of the host verdict (its largest test is 152,483 bytes, still over the budget) and a coverage audit of which seed lines a projection conveyed (not computable). On the channel node the seeds are about 603k tokens against a 475k-token window, so a codex judge's reading there is necessarily selective; the host holds it to what it read reaching it whole, and a smaller verdict-judge evidence set is a decision left open. `WORKSHOP_PROMPT_CONTRACT_VERSION` moves to `workshop-6`.
- **The codex judge pages through a host tool** (issue #534 PR-J3-a). Codex closing run (3) then refused five reads of the judge's own sizing: four chained several files into one command and sized by lines, none measured a file first, and two passed `max_output_tokens` below the default and then printed more than it — every one of which the reader row already told it not to do. The refusal held (40,963 bytes was over the rule), and the repair named the command and the leaf repeated its shape until the cut-read turns were spent and the producer restarted cold, which costs the phase an attempt. The decisions: the remedy is a host tool beside the refusal, not a wider refusal — a seed `read.py` in every codex reading tree pages a file under the advice size and prints the command for the next page, and the reader row leads with it; the advice size is half the byte rule, 20,000 bytes, so that a page survives a budget the leaf lowers on its own (it chose 7,500 and 8,500 tokens); a finding for a chained command says that two reads in one command are one output. Not done: more cut-read turns (moves the hole), a warm cut-read repair (rejected on #547), pre-paginated seeds (doubles the tree and leaves `cat` open), a raised codex output budget (none exists that a cut does not follow). Claude gets no helper (its `Read` pages and says so), and neither will the HTTP loop, whose `read_file` is planned to take a line range (PR-J3-b). `WORKSHOP_PROMPT_CONTRACT_VERSION` moves to `workshop-7`.

## Not adopted

- **Confining the `Build` and `Validate.execute` of the snapshot under `bwrap`.** Both run in the conductor's own process at the local site with no sandbox (`docs/BWRAP_ENABLEMENT.md`; `z4_enforcement_retirement.md` item 3), and as a submitted job at a remote site (issue #333). The judgment uses premise 1's decision criterion: what the operator's machine would gain is out of scope, and what a leaf would gain from the in-scope half — rewriting a snapshot file after the runner wrote it — is what Z6 already records as nil, because decoy storage gives the same value without it (`zero_base_architecture.md` Z6, the accepted residual). New evidence of a route that closure alone cuts reopens the item. The wrapper's runs (§Sandbox, second row) are a different case: they are confined because they are the leaf's own actions, not because of what they could reach.

## Fallback

When the A/B declines the shape, the producing leaves stay pure and two changes are made within that shape: the repair reply becomes a patch against the prior document that the host applies (no such form exists today), and `generate.generate` is produced in host-named parts as `compile.generate` is since issue #526. This keeps the one-reply model and its per-part prompt cost, and keeps the host responsible for splitting the work.
